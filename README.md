# Stock Market Game

A competitive, persistent, **multiplayer stock market simulator that lives in your terminal**.

One shared market. Every player trades against the same prices, the same news and
the same tape. Close your laptop, come back tomorrow, and your portfolio is
exactly where you left it — while the market kept running without you.

> **Virtual currency only.** No real money is ever involved, and no real company
> is ever traded. The 47 listed companies are fictional and every price is
> generated by a simulation.

## What it is

Think Investopedia's stock simulator, except:

- it runs in your terminal, not a browser;
- it is **multiplayer and persistent** — one world, always running;
- it is **competitive** — seasons, five leaderboards, achievements, a public trade tape;
- the market is **simulated but not random** — regimes, momentum, mean reversion,
  volatility clustering, sector rotations, earnings and news;
- your orders **move the price**, so other players see what you did.

The server is authoritative for everything that matters. The client draws pictures.

## Features

**Market**
- 47 fictional companies across 8 sectors, each with its own volatility, drift,
  beta and liquidity
- Bull / bear / neutral / panic / euphoria regimes that shift on their own
- Market-wide, sector-wide and company-specific news that actually moves prices
- Quarterly earnings, sector rotations, volatility clustering
- Simulated volume, market cap, day high/low, and an index (SGX)

**Trading**
- Market and limit orders, partial fills, cancellation
- Realistic spread, size-dependent slippage and permanent market impact
- Cash and shares are reserved when an order rests, so nothing double-spends
- Full order lifecycle: pending → partially filled → filled / cancelled / rejected

**Portfolio**
- Cash, holdings, average cost, market value, position weight
- Unrealised and realised P/L, today's P/L, total return, buying power
- Win/loss record, best and worst trades, a daily equity curve

**Competition**
- Five leaderboards: all-time, season, daily, weekly, monthly
- Seasons that reset rankings without ever touching accounts
- Public player profiles, 12 achievements, a live global trade tape

**Terminal UI**
- Unicode candlestick and Braille line charts with a volume strip
- 1D / 1W / 1M / 3M / 1Y timeframes, updating live
- Eight screens, fully keyboard-driven, responsive to terminal size
- Smooth partial redraws — only changed cells repaint, never the whole screen

## Quick start

Two terminals, about ninety seconds.

```bash
git clone https://github.com/SpikeForsythe/stock-market-game
cd stock-market-game
./install.sh --server        # installs client + server into .venv
```

**Terminal 1 — the server.** The first start generates the world (47 companies
and 400 days of price history). It takes a few seconds and happens only once.

```bash
.venv/bin/stockgame-server
```

**Terminal 2 — the game.**

```bash
.venv/bin/stockgame --server 127.0.0.1:8765
```

Press `R` to register. You start with **$100,000**. Press `?` at any time for the
key map.

## Installing the client

Players who only want to *play* need no server stack, no database and no Docker.

### Recommended: pipx

```bash
git clone https://github.com/SpikeForsythe/stock-market-game
cd stock-market-game
pipx install .
stockgame --server stocks.example.com
```

### With the installer

```bash
./install.sh            # client only
./install.sh --server   # client + server
./install.sh --dev      # editable install + test tooling
```

### With pip directly

```bash
python -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
pip install .
stockgame
```

### Platform notes

| | |
|---|---|
| **Linux** | Works out of the box. On Debian/Ubuntu you may need `sudo apt install python3-venv`. |
| **macOS** | Works out of the box. The stock Terminal is fine; iTerm2 and Ghostty look better. |
| **Windows** | Use **Windows Terminal**, not the legacy console, for correct Unicode and colour. PowerShell and Git Bash both work. python.org installers need *"Add Python to PATH"* ticked. |

Requires **Python 3.10 or newer**.

### The server address is remembered

```bash
stockgame --set-server stocks.example.com   # save it once
stockgame                                          # from then on, just this
stockgame --config                                 # show current settings
stockgame --logout                                 # end the stored session
```

Configuration lives in `~/.stockgame/config.toml`, written mode `0600` because it
holds your session token.

## Running a server

### Development

```bash
make server
# equivalently:
.venv/bin/stockgame-server --debug --tick-seconds 1 --day-seconds 300
```

A short `--day-seconds` is useful while developing: the simulated day rolls over
in minutes, so you can watch daily candles, snapshots and leaderboards work
without waiting an hour.

### Inspecting a running server

`stockgame-admin` reads the database directly, so it works whether or not the
server is up — and there is no network-exposed admin panel to attack.

```bash
stockgame-admin status                  # market, season, counts
stockgame-admin players                 # every account and its value
stockgame-admin player alice            # one account in detail
stockgame-admin market                  # all 47 symbols and prices
stockgame-admin trades --limit 50       # recent fills across all players
stockgame-admin news                    # recent market events
stockgame-admin promote alice           # grant admin rights
stockgame-admin suspend griefer         # disable an account, kill its sessions
stockgame-admin sessions --purge        # delete expired sessions
stockgame-admin halt LITH               # halt trading in one symbol
stockgame-admin season --end            # end the season early
```

The **first account to register becomes the admin**. After that the flag can only
be granted with `stockgame-admin promote`.

```

├── src/stockgame/
│   ├── shared/            # wire protocol, enums, money, validation
│   │   ├── protocol.py    #   frame format + channel names (stdlib only)
│   │   ├── money.py       #   integer-cent arithmetic and formatting
│   │   └── validation.py  #   rules BOTH sides run; only the server enforces
│   │
│   ├── server/            # the authoritative world
│   │   ├── market/        #   pricing.py (the model), engine.py, news.py, universe.py
│   │   ├── services/      #   auth, trading, execution, portfolio, leaderboard, …
│   │   ├── api/           #   routes.py (REST), websocket.py (gateway), hub.py (fan-out)
│   │   ├── db/            #   SQLAlchemy models, async engine
│   │   ├── core/          #   security, events, rate limiting, the game loop
│   │   ├── app.py         #   FastAPI factory
│   │   └── admin.py       #   the stockgame-admin CLI
│   │
│   └── client/            # the terminal UI — renders, never decides
│       ├── screens/       #   auth, dashboard, views, dialogs
│       ├── widgets/       #   chart.py (candles + Braille), panels.py (chrome)
│       ├── transport.py   #   reconnecting multiplexed WebSocket client
│       └── state.py       #   a read-only mirror of what the server said
│
├── tests/                 # 264 tests: unit + integration
├── migrations/            # Alembic
├── docker/                # Dockerfile, nginx, systemd, compose overlays
└── docs/                  # ARCHITECTURE, DEPLOYMENT, DEVELOPMENT
```

**The client is not trusted with anything.** It can ask to buy 100 ACME; it cannot
state what ACME costs, what its balance is, or what it owns. Prices, balances,
holdings, fill prices, valuations and rankings are all computed server-side and
sent down as finished numbers. See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

**Technology**

| Layer | Choice | Why |
|---|---|---|
| TUI | [Textual](https://textual.textualize.io) + [Rich](https://rich.readthedocs.io) | Real layout engine, CSS, partial redraws, identical on all three platforms |
| Transport | WebSocket + a small REST surface | Push, not polling; REST only for register/login |
| Server | FastAPI + Uvicorn | ASGI, WebSockets, dependency injection, async throughout |
| Database | SQLAlchemy 2.0 async + SQLite | Zero-setup deployment; the same models run on PostgreSQL |
| Migrations | Alembic | CI fails if the models drift from the migrations |
| Passwords | argon2-cffi (Argon2id) | The PHC winner. No cryptography is hand-rolled anywhere |

## How the market simulation works

Prices are not a random walk with a nice name on it. Each tick, every stock's log
return is the sum of five effects (`server/market/pricing.py`):

1. **Drift** — the company's long-run expected return.
2. **Market factor** — *one* shared shock per tick, scaled by each stock's beta.
   This is why the whole board goes red together, and why `AURM` (negative beta)
   rallies when everything else falls.
3. **Idiosyncratic diffusion** — the stock's own noise, with GARCH-style
   volatility clustering, so calm and turbulent stretches persist.
4. **Momentum** — an EMA of recent returns fed back at 18%, giving trends a
   little self-reinforcement before they exhaust.
5. **Mean reversion** — a pull toward a slowly drifting *fair value*, which is
   itself a random walk. This is what makes long-run winners and losers real
   rather than a coin-flip on who bought the highest beta.

Everything is expressed **per unit of time, not per step**, so the model behaves
identically whether it is stepped once per simulated day (history generation) or
1,800 times (live ticks). A test asserts exactly this — it is the bug class that
makes a naive simulated market explode.

**News does not move the price directly.** A headline shifts *fair value* and
injects a decaying shock, producing a sharp move followed by a realistic partial
retracement. Illiquid names gap harder on the same news.

**Regimes** (bull, bear, neutral, panic, euphoria) bend drift, volatility and news
sentiment, and transition on a Markov chain with exponential dwell times — so a
crash decays into a bear market far more often than it flips straight to a rally,
and nobody can time when a regime will end.

**Your trades matter.** Orders pay a spread that widens on illiquid names, plus
square-root slippage on size, and about 35% of that impact sticks permanently. A
large order visibly moves the tape for every other player.

On first run the engine fast-forwards the *same model* at daily resolution to
generate 400 days of end-of-day candles, so 1M/3M/1Y charts are useful from your
very first login.

## Configuration

### Server

Everything is environment variables — [`.env.example`](.env.example) documents all
of them. The ones that matter:

| Variable | Default | Notes |
|---|---|---|
| `STOCKGAME_SECRET_KEY` | *generated* | **Required in production.** Without it, sessions die on restart. |
| `STOCKGAME_DATABASE_URL` | `sqlite+aiosqlite:///./data/stockgame.sqlite3` | Swap for `postgresql+asyncpg://…` with no code change. |
| `STOCKGAME_STARTING_CASH` | `100000` | Per new account. |
| `STOCKGAME_TICK_SECONDS` | `2.0` | Real seconds between price ticks. |
| `STOCKGAME_DAY_SECONDS` | `3600` | Real seconds per simulated trading day. |
| `STOCKGAME_TRUST_PROXY_HEADERS` | `false` | Set `true` **only** behind a proxy you control. |

### Client

`~/.stockgame/config.toml` — server address, per-server session tokens, chart
style, default timeframe. Managed with `stockgame --set-server` / `--config`.

## Tests

```bash
make test            # 264 tests, ~35 seconds
make test-cov        # with an HTML coverage report
make lint            # ruff check + format check

```

Covered: registration, login, password hashing, session expiry and revocation,
rate limiting, admin access control, buying, selling, insufficient funds,
insufficient shares, limit orders resting and filling, cash and share
reservation, cancellation, portfolio valuation, cost-basis arithmetic across
partial sells, P/L, leaderboards, seasons, achievements, the price model's
step-size invariance and realised volatility, news generation, chart rendering at
every edge case, the WebSocket protocol, multiplayer isolation, anti-cheat,
concurrent traders, and full restart persistence.

CI runs the suite on Python 3.10–3.13 on Linux plus macOS and Windows, builds the
Docker image and smoke-tests it, and fails if the models drift from the migrations.

## Production deployment

Full walkthrough in [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md). The short version
for `stocks.example.com`:

```bash
git clone https://github.com/SpikeForsythe/stock-market-game /opt/stockgame
cd /opt/stockgame
cp .env.example .env
python3 -c "import secrets; print('STOCKGAME_SECRET_KEY=' + secrets.token_urlsafe(48))" >> .env
docker compose up -d
```

Then put nginx in front — a ready config, including the WebSocket upgrade block
the game needs, is in [`docker/nginx.conf`](docker/nginx.conf) — and get a
certificate:

```bash
sudo certbot --nginx -d stocks.example.com
```

Players then connect with:

```bash
stockgame --server stocks.example.com
```

The container runs as an unprivileged user, binds to loopback only, applies
migrations on start, and persists the database in a named volume.
**Docker is only ever needed for the server** — never for the client.

## Contributing

```bash
./install.sh --dev
make test lint
```

- Keep the client dumb. If a number can be computed on the server, it must be.
- Money is integer cents everywhere. Floats are for chart geometry only.
- Add a test with any behaviour change; CI will not merge without a green suite.
- Run `make format` before pushing.

The codebase is laid out so that the pieces most likely to be replaced — the
execution venue, the price model, the database backend — sit behind narrow
interfaces. [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) has a section on
extending it: real market data, short selling, options, dividends, margin, AI
traders, private leagues.
